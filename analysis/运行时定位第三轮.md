# CarX Street 1.23 雪花参数：第三轮运行时路径核验

本轮仍基于用户提供的 1.23 ARM64 `libil2cpp.so` 做静态核验，未在真机运行。

## 新确认的更直接定位路线

1. `UnityEngine.Rendering.RenderPipelineManager` 在 `UnityEngine.CoreModule.dll` 中有静态字段 `s_CurrentPipeline`，dump 中偏移为静态字段区 `0x18`。
2. 当前管线对象 `RenderCore.RenderPipeline` 的 `m_particleEffectSystem` 实例字段位于对象 `+0xB0`。
3. `RenderCore.ParticleEffectSystem.m_snowFX` 位于对象 `+0x10`。
4. `RenderCore.SnowParticleEffect.sizeMinMax` 位于对象 `+0x80`。
5. `Vector2ParameterMod.CopyValue` 的指令直接复制对象 `+0x14` 的 8 字节，因此该 Vector2 的 x/y 分量为 `+0x14`、`+0x18`；覆盖状态为 `+0x10`。

这条路线可以避免此前 `VolumeStackMod.GetComponent(int)` 需要先猜/求出类型哈希键的问题。计划使用导出的 IL2CPP API 查找程序集、类和字段，再通过 `s_CurrentPipeline → m_particleEffectSystem → m_snowFX → sizeMinMax` 取得对象。

## 更新机制再核验

`ParticleEffectSystem.SimulationStep()` 在 frame ID 变化时调用 `UpdateEmitterList()`，随后检查对象 `+0x20` 的 `m_emitterListIsDirty`。若为 true，会把 emitter list 上传，并清除 dirty 标志。因此控制端在更改 sizeMinMax 后把 dirty 标志置 true，是静态代码路径支持的更新策略；但它是否能在目标设备上稳定生效，仍必须真机验证。

## 本轮写入的源代码

- `native/snow_runtime_control.cpp`：IL2CPP API 定位、倍率读取、尺寸值写入与 dirty 标志设置。
- `native/zygisk_module.cpp`：仅在 `com.carxtech.sr` 进程中启动控制器的 Zygisk 入口源代码。
- `app/`：悬浮窗控制端的 Android 源代码；可拖动窗口，滑块范围 0.25×–3.00×，通过 SukiSU root shell 写 `/data/local/tmp/carx_snow_multiplier`。
