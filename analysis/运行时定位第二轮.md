# CarX Street 1.23 雪花参数：第二轮静态核验

目标仅为用户提供的 1.23 正式版 `libil2cpp.so` 与 dump。以下是静态反汇编结论，不等于真机运行时验证。

## 本轮新增确认

### 1. `Vector2ParameterMod` 内部 Vector2 值偏移更正为 `0x14`

`RenderCore.Vector2ParameterMod.CopyValue` RVA `0xBCCAA40` 的 ARM64 指令：

- `ldur x8, [x1, #0x14]`
- `stur x8, [x0, #0x14]`

该方法把源参数对象 `+0x14` 的 8 字节直接复制到目标参数对象 `+0x14`。因此在当前二进制的类布局中，Vector2 的两个 float 数据位于参数对象偏移 `0x14` 与 `0x18`，而不是此前推测的从 `0x18` 开始。`m_OverrideState` 在 `0x10`，与该布局相符。此结论来自实现指令，可信度高于仅凭 dump 字段泛型偏移的推断。

### 2. 活动 VolumeStack 的入口字段与 `GetComponent(int)` 访问方式

- `VolumeManagerMod.get_stack()` RVA `0xBCC6E88` 只是读取 manager 对象 `+0x10` 并返回。
- `VolumeStackMod.componentArray` 字段偏移 `0x10`。
- `VolumeStackMod.components` 字段偏移 `0x18`。
- `VolumeStackMod.GetComponent(int)` RVA `0xBCC7E94`：先从 stack `+0x18` 取出字典并用传入整数查索引；再从 stack `+0x10` 取 componentArray，检查数组长度，最终从数组元素区取出对应组件。

这说明 `GetComponent(int)` 的整数参数不是对象地址，而是用于查找组件索引的类型键。若要走这条路线，仍需从运行时类型表/字典中可靠地取得 `SnowParticleEffect` 对应键；不能随意把任意整数传入并假定返回雪花组件。

### 3. 尺寸参数到 emitter 的已知路径

- `SnowParticleEffect.sizeMinMax`：SnowParticleEffect 对象 `+0x80`。
- `ParticleEffectSystem.m_snowFX`：ParticleEffectSystem 对象 `+0x10`。
- `ParticleEffectSystem.m_emitterListIsDirty`：ParticleEffectSystem 对象 `+0x20`。
- `UpdateEmitterList()` RVA `0xBCA2D74` 会从 snow effect 的 `+0x80` 取参数对象，再通过虚调用读取 Vector2 值，并把两个分量写入临时 emitter config 的 size 分量。
- `SimulationStep()` RVA `0xBCA32B4` 中存在对 `UpdateEmitterList()` 的调用，并检查 dirty 标志。
